# DESIGN

公開画面の視覚設計を定める。実装とデザインデータは、どちらもこの文書を正とする。

対象利用者と成功条件は `PRODUCT.md` にある。ここでは見た目と構造だけを扱う。

## 方向

**発着案内板。**

このリーグのグループステージで敗退するチームはない。順位が決めるのは「通過か敗退か」ではなく、次の段階を**どこから始めるか**である。だから画面は勝敗表ではなく行き先表として組む。確率の一覧に「行き先」を後付けするダッシュボードにはしない。

情報構造は3案の比較で決めた（issue #8 のコメントに記録）。1〜6位を列に置いた順位マトリクスを採用し、分布バー案と行き先集約案は不採用とした。

## 配色

深い藍鉄の盤面に温白の文字、確率は琥珀ひとつの階調で表す。面の塗りは使わず、罫は横のみ。

| トークン | 値 | 用途 |
| --- | --- | --- |
| `--board` | `#0a1014` | ページ地 |
| `--panel` | `#0e171d` | 盤面（テーブル、凡例）の地 |
| `--panel-lift` | `#132029` | 盤面の中の一段明るい面 |
| `--rule` | `#1d2c35` | 見出しとの区切り罫 |
| `--rule-soft` | `#16232b` | 行間の罫 |
| `--ink` | `#e9efec` | 主要な文字 |
| `--ink-dim` | `#93a7ae` | 副次的な文字、記号の線 |
| `--ink-faint` | `#7d9099` | 見出しラベル、成績 |
| `--amber` | `#f2ab2e` | 確率（高） |
| `--amber-mid` | `#dda13a` | 確率（中） |
| `--amber-low` | `#c08b30` | 確率（低） |
| `--zero` | `#8f9aa0` | 確率ゼロ |
| `--settled` | `#ffffff` | 確定（100%）の値 |

配色は暗い側を採る。試合直後と試合前という利用場面から、夜のスマホで見られる前提とする。

### 触ってはいけない点

**この4つはコントラストを実測して決めた値である。目分量で暗くしない。**`--panel` を地としたときの比は次のとおり。

- `--amber-low` 6.02:1、`--amber-mid` 7.97:1、`--amber` 9.18:1、`--ink-faint` 5.45:1、`--zero` 6.30:1

色の階調が圧縮されて見えるのは意図どおりである。確率の大小は色ではなく後述の下線が担うので、色相の幅を稼ぐために4.5:1を割ってはいけない。

**ゼロは琥珀の最下段ではなく中性の灰にする。**ゼロは「わずかな確率」ではなく「その順位はあり得ない」を意味するので、色相を分ける。

## 書体

| 役割 | 書体 |
| --- | --- |
| 見出し、チーム略称、数値、ラベル | TeX Gyre Heros Cn |
| 日本語 | システムのゴシック（Hiragino Kaku Gothic ProN → Yu Gothic Medium → Noto Sans JP） |

TeX Gyre Heros Cn はHelvetica系の縮長で、空港サインの系譜にある。GUST Font License で再配布可。

`@font-face` は `unicode-range` を `U+0000-00FF, U+2013-2014, U+2026, U+2212` に限定し、日本語はシステム側へ落とす。

**Nimbus Sans Narrow は使わない。**AGPL-3 でフォント例外がPostScript/PDFへの埋め込みに限定されており、Webページへの埋め込みは例外の範囲外になる。

## 盤面の構造

8列。`<colgroup>` で幅を指定する。

| 列 | 幅 | 内容 |
| --- | --- | --- |
| チーム | 25% | 現在順位（小）＋略称（太）／正式名と成績（狭い画面では成績のみ） |
| 直通 | 14% | 1位＋2位の合算 |
| 1〜5位 | 各 9.66% | 順位別確率 |
| 6位 | 12.7% | 順位別確率（右端の余白を含む） |

### 列幅の罠

`table-layout: fixed` は**最初の行**から列幅を決める。行き先の帯が1行目に来るので、2行目のセルに書いた幅指定は効かない。**必ず `<colgroup>` の `<col style="width:…">` で指定する。**

旧実装にあった `table { min-width: 930px }` を復活させない。これが横スクロールの原因だった。幅375pxで `document.documentElement.scrollWidth === 375` を満たすこと。

### 行き先の帯

順位の列の上に、行き先を `colspan` で帯として置く。

| 帯 | かかる列 | 短縮 | 正式 |
| --- | --- | --- | --- |
| 1位 | 1列 | `bye` | Playoffs Upper Bracket 準決勝へbye |
| 2位 | 1列 | `PO1` | Playoffs Upper Bracket 1回戦 |
| 3・4位 | 2列 | `PI2` | Play-In Upper Bracket 2回戦 |
| 5・6位 | 2列 | `PI1` | Play-In Upper Bracket 1回戦 |

短縮形は620px未満、正式名は620px以上で出す。

**行き先を各チームの行に出してはいけない。**行き先は順位の属性であってチームの属性である。最も確率の高い順位の行き先を行に出すと、29%にすぎない結果が確定した事実のように読める。この設計は一度作って却下した。

### 行き先の記号

ブラケット上のトラックに入場位置を打つ図。29×10のSVG、`viewBox="0 0 29 10"`。

- 横線 `x1=2 y1=5 x2=27 y2=5`、`stroke-width=1`
- 目盛 `x=4, 11, 18, 25` を `y=2.5` から `7.5` へ
- 入場位置に `r=3` の塗り円。bye は `x=25`、PO1 は `18`、PI2 は `11`、PI1 は `4`

右にあるほど遅く入る＝有利。線は `--ink-dim`、円は `--amber`。

絵文字や記号文字で代用しない。

### 確率のセル

数値の下に、幅が確率に比例する2pxの下線（`.gauge`）を置く。`currentColor`、`opacity: 0.55`、右寄せ。幅は `max(9, round(v * 100))%`。ゼロのときは下線を出さない。

これが色以外の第2の経路になる。**色を無効にしても大小が読めることが要件。**

表記は次のとおり。

| 値 | 表示 | 色 |
| --- | --- | --- |
| 1 | `100` | `--settled`（太字） |
| ≥ 0.4 | 整数% | `--amber` |
| ≥ 0.12 | 整数% | `--amber-mid` |
| > 0.005 | 整数% | `--amber-low` |
| > 0 | `<1` | `--amber-low` |
| 0 | `0` | `--zero` |

## ページ構成

- 公開ページは大会タブと説明タブを切り替える。大会一覧APIは未実装なので、大会タブはハードコードした1件の配列から組み立てる。配列を増やせばタブが増える構造にする
- 管理者ページは別URLへ置く。ルータライブラリは追加せず、`pathname` の分岐で足りる
- タブは WAI-ARIA Tabs パターンを満たす。`aria-selected`、`aria-controls`、左右矢印での移動、roving tabindex

外枠は `max-width: 860px`、左右の余白は14px。

## 説明タブ

見出しは4つ。「この数字は何か」「順位が決めるもの」「同率のとき」「正確でないところ」。

モデルの前提（100,000回試行、残り試合を一律50%、スコア生成の簡略化）と、公式タイブレーク5基準、3チーム以上のsubgroup規定、Liquipediaの出典とライセンス、非公式である旨を置く。

「正確でないところ」を省かない。残り試合を一律50%としている以上、分析用途に耐えないことは書いておく。

## 画面の状態

3系統だけ実装する。

| 状態 | 扱い |
| --- | --- |
| 読み込み中 | `aria-live` で通知 |
| 取得成功 | 盤面を表示 |
| 取得失敗 | 理由を示し、再試行できる。`aria-live` で通知 |

古いデータや欠損の防止はWorker側の責務とし、フロントへ持ち込まない。ただしAPIレスポンスに欠損があった場合、黙って非表示にせず欠損として表示する。

## 動き

盤面のフリップなど、案内板の比喩から来る動きは入れない。装飾になる。`prefers-reduced-motion: reduce` では残った遷移も止める。
