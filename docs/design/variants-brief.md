# 視覚案の生成指示

issue #8 の視覚方向を選ぶためのモックを作る指示。人間が見比べて1つ選ぶのが目的。

**雑でよい。数とスピードを優先する。**作り込みや検証より、方向性の幅を出すことを優先する。

## 成果物

`docs/design/variants.html` に自己完結した単一HTMLを1つ。

- 上部で案1〜8を切り替える（クリックと左右矢印キー）
- 幅を「375px」と「全幅」で切り替える。375pxではキャンバスをその幅に固定する
- 外部リソースを読まない。CSS・JSはインライン。CDN、外部フォント、外部画像は禁止（公開先のCSPでブロックされる）
- `<!DOCTYPE>` `<html>` `<head>` `<body>` は書かない。`<title>`、`<style>`、本文、`<script>` を直接書く

## 固定するもの

### 表の構造

8列。チーム（現在順位＋略称＋正式名と成績）／直通（1位+2位の合算）／1〜6位の各確率。

- 1〜6位は均等な重みで並べる
- グループAlphaとOmegaを縦に並べる。タブで分けない
- 順位と行き先の対応（1位=Playoffs準決勝へbye、2位=Playoffs UB 1回戦、3・4位=Play-In UB 2回戦、5・6位=Play-In UB 1回戦）が画面のどこかで分かること。表現方法は案ごとに変えてよい

### データ

```sh
git show 956b84c:apps/web/public/prototype-fixture.json
```

`standings.alpha` / `standings.omega` が順位順、`simulation.probabilities` に `teamId` `directPlayoffs` `positions`（6要素）、`teams` に `id` `name` `shortName`。値は書き換えない。

## 変えるもの

**色味、書体の組み合わせ、余白、罫線、確率の強調のしかた、見出しの扱い。**

8案は明確に別物にする。同じ配色の濃淡違いを並べない。明るい地と暗い地を混ぜてよい。

## 制約

- **発着案内板（空港のフリップボード）と、藍鉄＋琥珀の配色は禁止。**一度作って不採用になっている
- 情報密度を上げすぎない。1画面に詰め込んでどこを見ればいいか分からなくなるのを嫌われている
- 装飾を足さない。アニメーション、影、グラデーションなど情報に寄与しないものは入れない
- 幅375pxで横スクロールしないこと。`table-layout: fixed` を使うなら列幅は `<colgroup>` で指定する（`fixed` は最初の行から列幅を決めるので、ヘッダーが複数行だと2行目の指定が効かない）
- 確率の大小を色だけで表さない。長さや太さなど色以外の経路を持たせる
- 確率ゼロは「その順位はあり得ない」の意味。他の低い値と同じ見え方にしない
- **書体はシステムフォントスタックのみ。**フォントを埋め込まない（ライセンス確認と容量を避けるため）。日本語が出ることを確認する

## やらなくてよいこと

スクリーンショット撮影、コントラストの厳密な計算、`scrollWidth` の実測、詳細な自己評価。**時間をかけずに8案出すことを優先する。**
