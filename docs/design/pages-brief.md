# 説明ページと管理者ページの設計

`docs/design/mock.html` は確率テーブルだけで、**説明と管理者ページが抜けている。**この2つを足す。

**確定済みのデザイン言語をそのまま使う。**新しくデザインしない。

## 使うデザイン言語

`docs/design/mock.html` から読み取る。配色（白＋コバルト＋朱赤）、書体（アルファベット Public Sans、数字 Work Sans、`size-adjust: 107%`）、余白、罫線、見出しの扱い、タブの見た目。

守る下限も同じ。

- 375pxで `document.documentElement.scrollWidth === 375`
- コントラスト 4.5:1 以上（大きい文字は 3:1）
- タッチターゲット 44×44px 以上
- `prefers-reduced-motion: reduce` 対応
- `:focus-visible` の可視フォーカス
- 装飾を足さない（影、グラデーション、角丸、アニメーション）

## 1. 説明

### 置き場所

**ヘッダーの右端。**大会タブ（`Pacific`）とは別の位置に置く。大会が増えても大会名の列に異質な項目が混ざらないようにするため。

現在ヘッダーには「VCT QUALIFICATION」がある。その行の右端が候補。狭い画面で見出しと重ならないこと。

表示方法（同一ページ内の切り替えか、別パネルか）は設計で決めてよい。決めた理由を報告すること。

### 内容

`docs/PRODUCT.md` と issue #8 に基づく。次を必ず含める。

**この数字が何か**
残っている試合の勝敗をすべて五分（50%）と置き、グループの全試合を100,000回くり返し組み立て直したときに、各チームがその順位で終わった割合。予想ではなく、今の勝敗表から機械的に数えた結果。

**順位が決めるもの**
このグループステージで敗退するチームはない。12チーム全員が次へ進み、順位はどこから始めるかだけを決める。

- 1位 — Playoffs Upper Bracket 準決勝へ bye
- 2位 — Playoffs Upper Bracket 1回戦
- 3・4位 — Play-In Upper Bracket 2回戦
- 5・6位 — Play-In Upper Bracket 1回戦

**同率のとき**
公式規定の順で判定する。①直接対決の勝敗 ②直接対決のマップ差 ③直接対決のラウンド差 ④マップ差 ⑤ラウンド差。3チーム以上が並んだ場合は、上位と判定できたチームを切り離し、残りをひとつの組として最初の基準からやり直す。

**正確でないところ**
残り試合を一律50%としているため実力差が反映されない。マップ数とラウンド数の生成も簡略化しており、同率の判定に影響する。分析用途には向かない。

**出典**
Liquipedia VALORANT Wiki（CC BY-SA 3.0）。Riot Games、VALORANT Esports、Liquipediaとは無関係の非公式サイトである旨。

この画面は読ませるためのものなので、**本文の行長を65〜75文字程度に収める。**表の画面とは別の組み方でよい。

## 2. 管理者ページ

### 位置づけ

運用者（リポジトリ所有者）ひとりが、日次更新が動いているかを確かめ、必要なら手動で取り込むための画面。ファン向けの公開画面とは利用者も目的も違う。

**別URLに置く。**モックでは切り替えボタンで到達できるようにしてよいが、それが仮の導線であることが分かる形にすること。

### 内容

issue #7 の初期スコープに基づく。

- 最新の成功・失敗・変更なしジョブの表示
- 各ジョブの開始時刻、終了時刻、実行時間、エラー概要
- 最新スナップショットの取得日時、source revision、content hash
- 最新シミュレーションの生成日時、seed、iterations、実行時間
- 手動更新の実行。**確認を挟む**こと。実行中は二重送信を防ぐ
- 実行結果（成功・変更なし・失敗）を識別できる表示

### 状態

次を作り分ける。データはもっともらしい値を自分で作ってよい。

- 直近が成功
- 直近が失敗（エラー概要あり）
- 直近が変更なし
- 手動更新の実行中（二重送信できない状態）

**成功・変更なし・失敗を色だけで区別しない。**文言か記号を併用する。

### エラー表示

秘密情報や外部レスポンスの生データを含めない。何が失敗したかと、次に何をすればよいかが分かる粒度にする。

## 成果物

`docs/design/mock.html` に統合する。確率テーブル、説明、管理者ページを1ファイルで行き来できるようにする。

既存の確率テーブルのレイアウトとデータは変えない。

## 制約

- `docs/design/` 以外を触らない
- コミットしない
- 依存を追加しない
- `.fig` は作らない（人間の確認後に別依頼で作る）
- 中間ファイルは `/tmp` へ

## 検証

- 375pxでの `scrollWidth`
- コントラスト基準割れの件数
- タッチターゲットの実寸
