# 公開画面と管理者ページの実装

`apps/web` を、確定したデザインで作り直す。issue #8 の実装フェーズ。

現在の `apps/web/src/App.tsx` と `styles.css` は**不採用になった旧デザイン**（発着案内板）のまま。丸ごと置き換える。

## 正本

- **`docs/design/mock.html`** — 視覚の正本。配色、書体、余白、罫線、3画面の構造、タブ、状態表示がすべてここにある
- **`docs/DESIGN.md`** — トークンと守る下限、実装時の注意
- **`docs/PRODUCT.md`** — 対象利用者と成功条件
- `packages/shared/src/types.ts` — `EventPayload` の形

**見た目は `mock.html` を正とし、勝手に変えない。**

## 作るもの

### 公開ページ（`/`）

- 大会タブ（現時点で `Pacific` のみ）とグループタブ（Alpha / Omega）
- 確率テーブル8列（チーム／Playoff／1位〜6位）
- ヘッダー右端から「説明」へ切り替え

データは `${API_BASE}/api/events/${EVENT_ID}` から取得する。

大会一覧APIは #9 の担当なので、**大会タブはハードコードした1件の配列から組み立てる。**配列を増やせばタブが増える構造にすること。

### 説明

`mock.html` の内容をそのまま。モデル前提、順位が決めるもの、同率の規定、正確でないところ、出典と非公式である旨。

**APIを必要としない。**取得に失敗している間も読めること。

### 管理者ページ（`/admin`）

`mock.html` の管理者ページをそのまま。4状態（成功／変更なし／失敗／実行中）。

管理APIは #7 の担当なので**モックデータで実装する**。

**#7 が完了するまで本番ビルドから到達できないようにすること。**ビルドフラグで除外するか、ルーティングへ登録しない。ビルド成果物に管理画面の経路が残っていないことを確認する。

### 画面の状態

読み込み中 / 取得成功 / 取得失敗の3系統。`aria-live` で通知し、失敗時は再試行できる。

**取得失敗でページ全体を差し替えないこと。**ヘッダーとタブは常に描き、状態の差し替えは大会タブの中だけに閉じる。説明タブはどの状態でも読める。

## 必ず守ること

`docs/DESIGN.md` の「守る下限」と「触ってはいけない点」を全部満たす。とくに次。

- `<colgroup>` で列幅を指定する。`table-layout: fixed` は最初の行から幅を決めるため
- `table { min-width: 930px }` を復活させない。これが横スクロールの原因だった
- 配色トークンの値を変えない。コントラストを実測して決めた値
- 書体は Public Sans（ラテン）と Work Sans（数字）。`unicode-range` で振り分け、Work Sans に `size-adjust: 107%`
- フォントは `apps/web/public/fonts/` へ置き、`url()` 参照にする。base64インラインにしない
- ライセンス全文を `apps/web/public/fonts/` へ置く

## モック専用の枠は持ち込まない

`mock.html` の次は本番に入れない。

- 幅の切り替え（375px / 全幅）
- 管理者ページの状態切り替え
- 「管理者（仮）」の導線

## 撤去するもの

- 旧書体 TeX Gyre Heros Cn（`apps/web/public/fonts/texgyreheroscn-*.otf` と `LICENSE-TeXGyre.txt`）。使わなくなる

## 制約

- ルータライブラリを含め、依存を追加しない。経路は `/` と `/admin` の2つだけなので `pathname` の分岐で足りる
- `docs/` を変更しない
- コミットしない

2. 幅375pxで `document.documentElement.scrollWidth === 375`（3画面とも）
3. コントラスト基準割れ0件
4. キーボードだけでタブ切替と全チームの確率へ到達できる
5. 取得失敗時も説明が読める
6. 本番ビルドから `/admin` へ到達できない
